# 原主场景的任务约束与停靠—导航对照协议

实验 ID：`main_joint_task_navigation_20261111`。日期：2026-11-11。

本文件规定冻结输入、方法和证据边界，不填写正在生成的性能数字。运行状态见 `run_state.json`；`RUNNING` 时的 CSV 是进度快照。完整运行包含三种任务 × 四种方法，共 12 个案例，失败案例也计入完成记录。

## 保留原场景与全部任务

- 直接读取 `scene_config()` 并用 `build_scene_from_cfg` 构建原主场景，不改桌子位置、朝向、尺寸、地图、起点或任务采样参数。
- 原地图为 10×10 m、分辨率 0.05 m；16 张 1.2×0.4×0.5 m 桌，起点 (0.5, 0.5, 0)。
- 随机种子保持 2026，保留生成的全部 36 个任务。每桌原有 2–3 个任务，不根据机械臂求解结果挑选目标或删除失败任务。
- `metadata.json:source_scene_config`、`tasks.csv` 和 `main_setup.mat` 保存输入。协议测试用一次独立的默认场景重建核对地图、全部任务与配置。

## 共同几何候选子池

先沿用原候选生成器，在原场景和任务坐标上生成 **26,660** 个 dense 候选。按配置的 0.423×0.366 m 底盘矩形足迹进行统一碰撞过滤，保留 **8,692** 个 footprint 合法候选，再进行任务类型无关的几何预算采样，冻结 **906** 个子池候选。

采样规则对每桌每边最多保留 8 个 XY 位置，每个 XY 最多保留 2 个原有朝向，因此每桌上限为 64。XY 采用从边中点、法向距离约 0.30 m 的参考位置起始的确定性最远点采样；朝向从该位置已有的 dense 候选中选择最接近边法向、边法向加 15° 的可用项。参考值只用于选择已有候选，不额外补造 XY 或 yaw。

采样先完成底盘碰撞检查，随后仅依赖几何，不使用任务类型、IK 支持、代价优化结果或是否容易成功等信息。三种任务和四种方法使用同一候选 ID 与完整 SE(2) 位姿集合。记录包括：

- `dense_to_subpool.csv`：每个 dense 候选的身份、位姿、碰撞与保留标记。
- `candidate_pool.csv`：子池 ID、原 dense ID、所属桌/边、实际 XY/yaw；矩阵/回调节点 1 为起点，节点 2…N+1 按子池顺序排列。
- `table_candidate_counts.csv`：逐桌 raw、footprint 合法与最终保留数量。

本轮最少停靠证书只针对 **906 候选子池内、各桌所属候选—任务支持矩阵**。它不认证 8,692 个合法 dense 候选、全部 26,660 个原候选或连续空间中的最少停靠数。

## 三种任务与相同机械臂假设

所有方法均使用同一可选 VX300s 六关节模型、关节限位、TCP 和安装变换。原底盘尺寸不变；安装变换沿用规划器中的安装假设，尚未做实机标定。三种任务保留相同目标锚点，仅添加任务条件。

| 任务模式 | 目标/有序路径 | 姿态条件 |
|---|---|---|
| `position_only` | 原目标点 | 不限制方向 |
| `top_down_grasp` | 上方 4 cm 接近、目标点、撤离 | 工具 +X 轴朝下，10° 容差，允许绕该轴旋转 |
| `table_wipe` | 以原目标为中心、沿世界 X 方向 12 cm 的有序路径 | 完整 TCP 姿态，5° 容差，接触平面高度容差 3 mm |

位置容差为 3 mm，路径采样间距为 2 cm，相邻采样关节变化阈值为 25°；每条操作路径固定同一机械臂。初始 IK 使用最多 16 个确定性初值、每初值最多 120 次迭代，后续路径点以上一解作单初值。这里的任务设置覆盖模型默认容差，不能把模型默认的 2 mm/2° 当作本实验有效任务容差。

各模式使用相同附加工具变换和官方夹爪 TCP。擦拭条件是该 TCP 的运动学接触任务，不表示已经安装、标定或验证实体擦拭垫。抓取接近路径含高于桌面的点；任务锚点在桌面不意味着整条路径始终位于桌面。

三任务的动作路径、姿态自由度和部分容差同时不同，抓取与擦拭不构成严格的集合包含关系。其差异不能全部归因于姿态这一项。

## 支持矩阵与缓存

每个子池候选只评价其所属桌的全部原任务。分母由各桌候选数乘该桌任务数后求和；不得用 N×36 替代该分母，也不得删去求解失败的配对以提高支持比例。

每种任务单独建立数值 IK 缓存与支持矩阵，同一模式的四种方法复用同一份已评分库：

1. 量化仅用于检索可能相同的局部请求，不用于接受近似目标或近似失败结论。
2. 正见证复用前，对当前未量化请求逐样本重算 FK，检查位置/姿态残差、关节限位、相邻关节变化及适用的接触高度。
3. 负见证只在原始局部请求完全相同且失败原因属于允许的纯搜索失败集合时复用。另一臂的未知失败不能随正见证近似复用，必须重新求解。
4. 定期以同一原求解器复查缓存命中，记录命中、回退、直接复查、差异与“已有正见证但直接有限搜索未找到解”等计数。该复查仍不是独立 IK 验证。

正见证提供的是当前模型下的可行采样关节序列；它不保证重新执行一次有限多初值搜索会产生完全相同的结果。搜索失败也不证明物理上无解。

`pair_support_<mode>.csv` 保留所有成功/失败配对、失败位置、残差、关节步长与缓存事件；`candidate_support_<mode>.csv` 保留所有子池候选。`ik_cache_<mode>.json` 保存计数与证据边界，`candidate_library_<mode>.mat` 保存普通数据结构，不序列化缓存 Map。

库重用须匹配场景、任务约束、模型/预算、候选池、缓存策略及评分/FK/IK 源内容签名。目录共同签名防止不同几何或策略混写；签名不符应使用新输出目录，不覆盖旧证据。

## 四种方法

| 方法 | 操作 | 与前一控制的区别 |
|---|---|---|
| `staged` | 原 `bottom_up` 选停靠，沿用现有最近邻访问顺序，再生成导航路线 | 原分阶段基线 |
| `minimum_seed` | 以原方案为种子，必要时修复为逐区域最少覆盖；保留仍使用的原节点相对顺序，新节点占被替换的区域 slots；不做后续搜索 | 单独展示覆盖数修复的影响 |
| `reorder_only` | 固定相同修复后的最少停靠集合，只做有向 2-opt | 隔离访问顺序优化 |
| `joint_local` | 在当前区域访问 slots 中替换整组最少覆盖及区域内排列，并做有向 2-opt | 同时允许改变停靠集合与访问顺序 |

区域任务必须构成全部任务的无重叠完整划分。每个区域先以位掩码 DP 认证子池支持矩阵上的最少覆盖数，并枚举该层全部覆盖；局部策略不枚举 16 桌停靠的全局访问排列。

若原 greedy 停靠数大于该区域最少数，修复可能改变路线代价，因此必须分别报告 `input_seed_cost`、`minimum_seed_cost` 和最终代价。只能把局部严格下降归于修复后的共同种子，不把修复与后续优化混成同一来源的收益。

候选邻居可以用几何代理排序，但接受每一步必须依据真实有向导航边代价严格下降，阈值为 1e-9。有向 2-opt 重算反向段中的内部边，不使用仅适用于对称图的四边差公式。

本轮默认预算见 `metadata.json:local_search_budget`：最多 3 次 pass、1,500 个新边 oracle 请求、10,000 个邻居尝试、120 s 协作式时间检查、每区域至多 3 个停靠。时间在查询/搜索检查点判断，不会中断一个正在执行的 A* 调用。回调内部可命中共享导航缓存，因此新 oracle 请求数不等于新增 A* 计算次数。

预算耗尽返回已经完整定价且保持覆盖/区域最少数的 incumbent，并记录停止原因；初始最少种子尚未定价时明确失败。只有完整测试一轮已启用邻域且无改善时，才可标记相应邻域的局部最优。所有案例均 `global_optimal=false`，不声称全局、连续空间或物理最优。

## 统一导航目标与路线验收

实验显式统一使用 A*、所选服务节点上的 dense 路由、相同足迹/地图与返回同一起点条件。导航查询按有向边惰性记录并共享缓存，不构建全部子池节点的平方代价矩阵；`staged` 的访问顺序沿用仓库现有最近邻实现。

对完整往返服务序列，优化目标为：

\[
J=\sum_{(i,j)}\left(L_{ij}+0.15\,\left|\operatorname{wrapToPi}(\theta_j-\theta_i)\right|\right).
\]

其中 L 是实际 A* 导出路径的 XY 长度，角差是服务节点端点 yaw 之差，权重单位为 m/rad。**J 不是能耗，也不是沿路径累计转角或真实执行时间。** 原始路线长度 `route_length_m` 与加权 `navigation_cost` 分开报告。

最终路线仍由 Stage 3 实际拼接并检查底盘足迹、精确停靠端点、段连续性与回到起点；同时核对实际加权路线代价与局部 oracle 预测值。`navigation_paths.csv` 保存实际路径点，`navigation_edges.csv` 保存有向边的长度与加权代价。

本实验的 A*/dense 设置只是本次显式覆盖。原主入口仍使用原 `convex_astar`、`bottom_up` 和 `robot_config()` 历史模型；可选 VX300s 与局部策略不会自动替换主入口默认值。

## 失败、计时与证据边界

- 全部 36 任务预测覆盖、同一任务后端数值复核与底盘路线检查都通过时，才把该案例作为完整任务可比较结果。
- `BLOCKED`、`ERROR`、IK 复核失败、无完整覆盖和无有效路线均保留。可比较的路线长度与 J 为 `NaN`；保留的 raw 路线列只用于诊断，不能当成功结果或以少服务任务的短路作为优势。
- `verified_tasks` 是同一数值后端的复核计数，不是独立 IK 验证、仿真接触成功率或实机完成数。
- 逐任务检查不认证任务之间的机械臂过渡。安装标定、机械臂自碰撞/互碰/桌面避碰、采样点间运动、接触力、清洁效果与真实抓取完成均未验证。
- 模式和方法按固定次序运行，库可从磁盘重用，导航缓存跨方法共享。评分、选择、oracle 请求和实际新增 A* 查询分别记录；单次计时不是端到端公平效率基准，也不支持统计显著性或通用加速主张。
- 单个原主场景和一个任务种子支持受限定的机制判断；不据此宣布跨布局泛化、鲁棒性或算法新颖性。
