# 主场景机器人参数统一说明

日期：2026-10-27。

本次按用户要求，将 `main_mobile_manipulation_planning.m` 使用的 `config/robot_config.m` 作为唯一机器人参数来源。主入口与机器人配置文件中的数值不变。场景可以改变地图大小、桌子布局、任务数量与分布；机器人尺寸、安装位置、工作空间、DH 参数和关节限位保持一致。

后续进度：本文记录的是先前的模型清理阶段。随后按用户指定顺序开展的几何、实验口径和方法证据修复见 [修复报告](geometry_protocol_evidence_repair.md)。下文的43/44历史检查结果和“尚未修复”事项不代表后续修复状态；主入口的计时与校验已更新，唯一机器人配置的数值继续保持不变。

## 删除范围与原因

- 删除餐厅主入口、两个 demo、场景配置、运行/验证函数、二维服务代理候选库、专用绘图与12个专用测试。其桌面高度和服务代理口径与主场景不一致。
- 删除实机匹配实验的场景构建、配置、运行函数，以及 `scene_config.m` 末尾整段已注释的实机场景替代配置。该分支依赖另一套安装参数，任务点也存在桌外坐标定义。
- 删除 `physical_robot` 几何分支、专用参数测试、双模型对照实验及其结果表、专用参数审计说明。项目不再提供切换到另一套安装参数的入口。
- 删除上述场景的专用 CSV、JSON、TXT 和图像，以及实验管理器生成的专用输出。共删除81个文件，其中30个为 MATLAB 文件；精确清单、大小和删除前 SHA-256 见 [删除清单](main_robot_unification_removed_files.csv)。
- 从实验注册表、配置构建器和 GUI 中删除上述选项。通用 footprint 导出的默认目录改为 `results/footprint_validation`。

删除没有扩展到历史论文、汇报成品、清理保存点清单与通用接口。含旧场景的历史报告只反映当时版本；其中的入口、文件数和维护状态不再代表当前项目。它们不能作为当前单模型配置的实验依据。

## 保留范围

保留主场景、四桌八任务场景、C0–C3复杂度场景、L1–L3大规模场景、V1–V3可视化场景、困难/随机任务实验以及P5动态重规划。这些场景的机器人均取自 `robot_config()`；地图、任务及规划器实验开关仍按各实验定义变化。

`robot_geometry_profile()` 与 `robot_geometry_profile('legacy_validated')` 仅为旧实验脚本保留的同值接口，返回完整的 `robot_config()`，不再携带另一套参数。有效配置统一报告 `robot_config`。

`integration/`、`calibration/`、`experiments/real/` 和默认关闭的 `real_platform_config` 保留为通用数据交换、日志分析与适配接口。它们没有定义被移除的机械臂安装模型，也不属于当前维护的实机场景。

## 防止再次混用

新增 `config/validate_main_robot_config.m`，逐字段检查唯一机器人配置。配置解析器、实验构建器、统一实验运行器、Stage 1 和 Stage 3 对冲突参数明确报错。配置解析器和实验构建器也检查嵌入规划器的 `robot_cfg`；导航与停靠共享同一配置。

旧冻结状态允许附带 `legacy_validated` 元数据，但几何数值必须一致。8份保留的P3/P4状态均使用主场景几何；它们缺少后来新增的派生 `footprint` 字段和规划器内嵌的 `robot_cfg`，读取时由唯一配置补齐，不重写 MAT 文件。Stage 1、Stage 3和动态状态归一化入口均使用补齐后的同值模型。

通用低层碰撞/缓存函数仍允许人工几何夹具；离线径向约束反事实诊断仍可在局部副本上放松约束以定位失败原因。这些属于单元测试或诊断，不提供另一套规划机器人配置，也不作为主场景可行性结果。

## 验证与研究边界

新增 `test_main_robot_unification`，覆盖所有保留的命名场景、兼容别名、已删选项拒绝、各覆盖层冲突参数拒绝、直接规划入口拒绝以及旧冻结状态补齐。同步更新原配置、入口接口和核心正确性测试。

MATLAB R2022a 下最终运行22个测试文件、44项测试：43项通过，1项失败并标记为未完成。单独的四桌八任务结构与候选构建检查、8份冻结状态参数核对、13个修改源文件的语法检查与GUI类加载均通过。生产 MATLAB 代码中已没有餐厅或替代实机模型引用；主入口、`robot_config.m` 以及主场景可执行配置与改动前一致。

失败项为 `test_local_replan_preserves_unaffected_state/testDockInvalidationPreservesUnaffectedDocks`：旧 `p5_fixture_state` 未提供完整机器人/规划器配置，现有停靠修复代码读取 `cfg.reachability.threshold` 时触发 `MATLAB:nonExistentField`。使用 Git HEAD 中改动前的 `normalize_planning_state` 单独复现了相同的 `reachability` 缺字段异常；涉及的 `local_replan`、该测试和夹具均未改动。本轮保留并报告这个已有问题，没有修改任务模型以迎合测试。

实际结果记录于 [验证记录](main_robot_unification_validation.json)。本次未运行全量历史实验或全部测试目录。

历史主场景和大规模结果保留原值，没有在本次清理中重新计算。本次参数统一不代表已经修复旋转桌面栅格、底盘碰撞坐标轴、候选朝向参数判断、冻结场景映射或动态实验指标来源等此前分析的问题；这些需要分别修改和验证。
